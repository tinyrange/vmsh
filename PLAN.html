Implementation plan · July 2026

Every feature should teach itself.

A plan for executable vmsh tutorials that drive a real interactive session, verify user-visible behavior, record the terminal, and pair playback with labeled Markdown guidance on the website.

Issue #242
✓

Decision

Build one small vertical slice first. Keep contribution and release policy as guidance in AGENTS.md: pull requests exercise only relevant tours, while every release regenerates and tests the complete tour catalog from the release commit. Add automation only after real tours show where it is useful.

The model

One story, four representations

The executable story is the source of truth. The test result, recording, and published lesson are products of the same successful session rather than separately maintained documentation.

01 · Author

Write the story

A Starlark script drives vmsh through a PTY and labels teaching moments with Markdown.

02 · Execute

Use a real session

Start vmsh, select systems, type commands, send keys, resize, wait, and assert outcomes.

03 · Record

Produce one tour

Package asciinema-compatible terminal events and timed Markdown sections into one artifact.

04 · Publish

Teach the release

The website replays the terminal beside a navigable guide tied to an exact vmsh version.

Scope

Build the useful core, defer the machinery

In the first version
  • A Starlark runner controlling a genuine vmsh PTY session.
  • Actions for typing, special keys, terminal resize, waiting, and behavioral assertions.
  • An enhanced cast containing terminal events and timed Markdown sections.
  • A website player with playback, seeking, section navigation, and accessible prose.
  • One end-to-end tour demonstrating host and VM context switching.
  • Repository guidance covering PR and release expectations.
Explicitly deferred
  • Automatic dependency graphs that decide which tours a PR must run.
  • Mandatory PR-form validation or labels for exemptions.
  • A hosted authoring environment or visual tour editor.
  • Voice-over, raster video export, analytics, or user progress tracking.
  • Large-scale conversion of all existing documentation before the format settles.
  • A bespoke terminal emulator if an established browser renderer is sufficient.

Artifact contract

Portable terminal data plus vmsh teaching metadata

Preserve ordinary cast events. Add a versioned vmsh namespace for identity, provenance, and sections so generic players can ignore the teaching layer while the vmsh website can render it.

tours/context-switching/tour.star
def main(ctx):
    ctx.section(
        "Select Alpine",
        """
        Select the **Alpine** system context.
        vmsh waits until it is ready.
        """,
    )
    ctx.type("@alpine")
    ctx.enter()
    ctx.wait_prompt(system = "alpine")

    ctx.section(
        "Run ordinary commands",
        "Commands now run inside the selected VM.",
    )
    ctx.type("uname -s")
    ctx.enter()
    ctx.expect_line("Linux")

    ctx.section(
        "Return to the host",
        "Use `@host` without ending the session.",
    )
    ctx.type("@host")
    ctx.enter()
    ctx.wait_prompt(system = "host")

Operating policy

Fast during development, complete at release

Pull requests

Run only relevant tours

A user-visible change creates or updates the demonstrations it affects and links them in the PR description. Unrelated tours do not need regeneration. Relevance is a contributor and reviewer judgment documented in AGENTS.md, not an inferred dependency system.

Releases

Regenerate the whole catalog

From the tagged release commit, run every tour against the release binary. Publication fails if any tour fails. The successful casts become immutable documentation for that version; “latest” points to the newest stable set.

Delivery sequence

Five small phases with observable exits

Each phase leaves something testable behind. Avoid designing the complete catalog or enforcement model before one real tour works end to end.

01

Define the tour source and cast extension

Specify the smallest Starlark API, Markdown rules, section timing semantics, provenance fields, and schema-version behavior. Include a hand-authored fixture before building the runner.

Exit A fixture validates and renders without network access.
02

Drive vmsh through the PTY

Reuse the existing PTY driver and asciicast recorder. Add stable primitives for terminal input, special keys, prompt readiness, resize, and structured behavioral assertions.

Exit The context-switching story passes and emits a valid enhanced cast.
03

Build the website player

Load a local or release-hosted cast, replay terminal events, synchronize the active section, render sanitized Markdown, and support keyboard and reduced- motion preferences.

Exit The example tour is usable on desktop and mobile without an external embed.
04

Add repository guidance and author documentation

Add the agreed policy to AGENTS.md, document how to run and preview one tour, and provide a small template authors can copy.

Exit A contributor can add a second tour without reading runner internals.
05

Wire release publication

Run all tours against the tagged binary, validate every artifact, publish the versioned catalog with the website, and update the latest-stable pointer only after the full set succeeds.

Exit A release has a complete, immutable, tested set of guided tours.

Test strategy

Assert the user contract, not the recording’s shape

Runner

Behavior

Verify system selection, command routing, exit status, files, protocol state, and prompt readiness. Exercise a long-lived interactive session.

Artifact

Compatibility

Validate the header, monotonic events, legal terminal sizes, section bounds, schema version, and absence of prohibited secrets.

Website

Playback

Test loading, seeking, section synchronization, Markdown sanitization, keyboard operation, and an accessible transcript.

Avoid brittle checks

Do not assert wall-clock timing, ANSI decoration, incidental progress text, or exact explanatory prose. Normalize terminal size, locale, and color.

Keep publication safe

Run with a minimal environment, redact known sensitive values, reject unsafe Markdown, and never record credentials or private host paths.

Repository guidance

The initial policy belongs in AGENTS.md

AGENTS.md · proposed addition
## Tested Tutorials

User-visible features should include a guided terminal demonstration. A
demonstration consists of an automated vmsh session, a replayable terminal
recording, and labeled Markdown sections that explain the workflow.

Pull requests should create or update only the demonstrations relevant to their
user-visible changes and link those demonstrations in the PR description.
Unrelated demonstrations do not need to be regenerated or tested.

Before publishing a release, regenerate and test every demonstration using the
release commit. The website should publish those generated demonstrations as
documentation for that specific released version.

Treat demonstration scripts as behavioral tests. Assert meaningful outcomes
such as context transitions, command results, files, protocol state, and exit
status. Avoid making exact timing, incidental terminal output, or explanatory
prose part of the behavioral contract.

Definition of done

The vertical slice is complete when…

  • A checked-in Starlark story drives an actual interactive vmsh session.
  • The story proves host → VM → host context transitions behaviorally.
  • A passing run generates one schema-validated enhanced cast.
  • The cast remains usable as ordinary terminal replay data.
  • The website renders synchronized Markdown sections beside playback.
  • The player works with keyboard navigation and on a narrow viewport.
  • The artifact records the vmsh version and source commit.
  • AGENTS.md explains relevant-tour PRs and complete release regeneration.
  • Author documentation makes a second tour straightforward to create.
  • No release artifact can publish unless every release tour passes.
